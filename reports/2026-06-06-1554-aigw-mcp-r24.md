It cannot credibly attest that a call was allowed, why, or what it returned." —— **server-side 是 audit 唯一可信源**。wire shape 已落 Vaara MCP proxy（v0.42+ ship）。AIGW #11 gateway + mcp-proxy 可直接复用 JCS+detached signature，**audit log 不再依赖 client 报告**。

## 四、`static API key` 在 MCP 治理中的位置（用户特别要求）

MCP 协议层**不**为 static API key 提供 first-class 支持 —— auth 默认走 OAuth 2.0/2.1 + RFC 8414/9728 discovery。但实战有 **4 类合法用例**：

1. **Loopback / 本地 daemon**（如 Claude Desktop ↔ 本地 mcp-proxy）：自签 static key，OS 进程隔离 + `127.0.0.1` 是隐式 trust boundary。SEP-2742 posture = `optional`。
2. **CI / E2E 测试**（csharp-sdk #1855 conformance auth server）：test fixture 跳过 OAuth flow，对应 SEP-2343 elicitation 的 "no-auth fallback" 路径。
3. **Service-to-service 联邦**（内部 cluster mesh）：AIGW #11 推荐 "static API key + 短期 TTL + 严格 hostname allowlist" 作为最低级；**真正硬要求是走 SEP-1933 WIF**（SPIFFE JWT 替代）。
4. **MCP-over-WebSocket / 私 deploy**（SEP-1288）：早期 ad-hoc 部署用 `Authorization: Bearer <static>`，**应迁移到 CIMD**（SEP-2742 列出 CIMD 为合法 OAuth 注册方式之一）。

**MCP 治理对 static API key 的"姿态"**：

- **RFC 8707 resource indicator** 是 OAuth 框架 "硬加 static key-like 语义" 扩展 —— MCP 1614 issue 5/11 提了 `resource` 改 OPTIONAL（与 RFC 8707 对齐），open。
- **SEP-1488 `securitySchemes` in Tool Metadata** 显式列 "More scheme types can be added later without changing the shape of the field. (API keys, mTLS, etc.)" —— static API key 走**协议层 "future" 路径**而非 first-class。
- **rust-sdk #883 / python-sdk #2784 DCR `application_type="native"`** 是 "消灭 static key 用例" 的动作 —— CLI/desktop 不再需要预共享 secret。
- **csharp-sdk #1625 SEP-990 Enterprise Managed Auth** 是企业版 "消灭 static key 用例" 的另一动作 —— IdP 统一管理。

**AIGW 落点**（新增 5 条 → 累加 102 条）：**S-21** static API key 用例清单（4 类）必须文档化 + 各自 migration path（loopback→process-isolated token / CI→CIMD / S2S→SEP-1933 WIF / WS→CIMD）；**S-22** **不要**新增 first-class static API key gateway 端点 —— 等 SEP-1488 协议层定稿；过渡期允许 `auth=optional` 模式走 header 注入但 audit log 必须标 `auth_method=static_key`；**S-23** `auth_method` 必须在 audit log 五元组里（`request_id` / `server_id` / `tool_name` / `user_id` / `auth_method`），与 #2867 scoped auth receipt 三层对齐；**S-24** go-sdk #969 `ClockSkew` 30-60s 配云 IdP 漂移，gateway 与 IdP 之间 **必须**配 clock skew；crystal 漂移导致 token 误拒是 5xx 而非 401；**S-25** SEP-1933 Workload Identity Federation 优先于 static API key：SPIFFE JWT validation 在 gateway 终止，**static key 只作 fallback**（SDK 不支持 WIF 时）。
