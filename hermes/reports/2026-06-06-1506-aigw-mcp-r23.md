## 1. py-sdk #2718 merged（5/29）—— Transport session 绑定到 authenticated principal

[PR #2718](https://github.com/modelcontextprotocol/python-sdk/pull/2718) 5/29 16:48 UTC 合入。Streamable HTTP 与 SSE 两种 transport **记录**创建会话的 principal（OAuth client + issuer + subject），后续请求**必须**呈现同一 principal 才被接受；不一致则返回**与未知 session ID 同响应 404**（避免存在性泄漏）。SSE session 在连接关闭时同步清理（之前保留到 transport lifetime —— 内存泄漏源）。

| Server 配置 | 效果 |
|---|---|
| 无 auth / 非 BearerAuthBackend | 不记录 principal，比较永远通过 |
| BearerAuthBackend + verifier 填 `subject` + `claims["iss"]` | session key = `{client_id, issuer, subject}` |
| BearerAuthBackend + verifier 不填 | 缺失字段 `None`，比较降级到剩余字段 |

与 Go SDK `TokenInfo.UserID` / C# SDK `UserIdClaim` 对齐。**对 hosted MCP host + gateway**（多 end-user 走同一 OAuth client）这是必修 —— 之前拿到 session ID 后任何持有者都能复用（横向越权）。

**AIGW 落点 #1**：session 表按 principal 切片（不能单维度 session_id）；verifier 缺 `subject`/`iss` 必拒（不能降级 None，否则攻击者构造缺字段 token 命中降级路径）。

## 2. ts-sdk #2253 + #2254 RFC 8707 Resource Parameter 客户端落地（6/5 10:20/10:22 open）

[PR #2253 main](https://github.com/modelcontextprotocol/typescript-sdk/pull/2253) + [PR #2254 v1.x](https://github.com/modelcontextprotocol/typescript-sdk/pull/2254) 双线同时修。spec [Resource Parameter Implementation](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization#resource-parameter-implementation) 段**强制**客户端在 authorization 与 token request 上**都**带 RFC 8707 `resource` 参数（canonical server URI），**与** Protected Resource Metadata（RFC 9728）发现**无关**：

> The `resource` parameter MUST be included in both authorization requests and token requests.
> MCP clients MUST send this parameter regardless of whether authorization servers support it.

Bug：`selectResourceURL` 在 PRM 发现失败时返回 `undefined`，客户端漏发 `resource`。修法是从 canonical server URL 派生（与 RFC 9728 「aligns with」但不依赖），PRM 失败回退到 server URL 自身。

**为什么是生产级 hardening**：`resource` 是 RFC 8707 引入的**资源隔离**机制 —— 防止一个 token 被跨资源（cross-resource）滥用。漏发时攻击者可以把受保护资源 A 的 token 拿去敲 B（confused deputy）。

**AIGW 落点 #2**：自家 gateway 出 MCP server 时，PRM 端点（`/.well-known/oauth-protected-resource`）必须返回**精确路径匹配**的 `resource` URI；不打算支持 PRM 时 server URL 自身必须是稳定 canonical URI（**不能**带 query string、末尾 slash 不一致）。

## 3. ts-sdk #2177 RequestAborted error code 区分（6/5 06:37 open）

[PR #2177](https://github.com/modelcontextprotocol/typescript-sdk/pull/2177) 6/5 06:37 UTC 开。Bug：`Protocol._requestWithSchema()` 的 `cancel()` 把任何非 `SdkError` abort 原因无条件包成 `SdkErrorCode.RequestTimeout` —— 用户主动 `controller.abort(new DOMException('User cancelled', 'AbortError'))` 与真 60s timeout **同一错误码**。修法：新增 `SdkErrorCode.RequestAborted`，timeout 路径不动。553 case 全过 + 1 新 unit test 校验两条路径。

**为什么是生产级 hardening**：
- 成本归因：超时 = 后端慢 / 网络问题，需 retry；用户取消 = UI/UX 行为，**不**重试
- 监控告警：超时率上升 → 容量问题；取消率上升 → UX 问题，**两套 alert rule**
- agent 框架：用户 abort 后 retry 引擎要能跳过（避免「取消 → 重试 → 再次取消」死循环）

**AIGW 落点 #3**：所有 custom error code 在 gateway / 转发层做映射时**保留**原始 code（不要把所有超时/取消合并成同一 5xx/4xx），cost attribution、metric 维度按 code 切分。

## 5. mcp main #2866 ElicitationCompleteNotificationParams 抽出（6/5 12:57 open）

[PR #2866](https://github.com/modelcontextprotocol/modelcontextprotocol/pull/2866) 6/5 12:57 UTC 开。Bug：`ElicitationCompleteNotification` 是 schema 中**唯一**一个 `params` 还是 inline anonymous object 的 notification，其他 5 个（`CancelledNotification` / `ProgressNotification` / `ResourceUpdatedNotification` / `LoggingMessageNotification` / `SubscriptionsAcknowledgedNotification`）都用了 named `*NotificationParams extends NotificationParams` interface。

修法：抽出 `ElicitationCompleteNotificationParams extends NotificationParams`，让 `ElicitationCompleteNotification` 与之同构。`NotificationParams` 内部定义的 `_meta` 普适继承字段就自动落到 ElicitationComplete 上。Close [#2651](https://github.com/modelcontextprotocol/modelcontextprotocol/issues/2651)。`npm run check:schema` 127 examples 全过。

**为什么是生产级 hardening**：`_meta` 是 MCP 协议级 escape hatch（cache_hint / otel / client-session-id 都走它）。某 notification 没有 `_meta` 字段就意味着**所有走 `_meta` 的协议扩展（`cache_hint` SEP-2419、`otel` SEP-2448、`Mcp-Client-Session-Id` SEP-2822）都不能附着在这 notification 上**。

**AIGW 落点 #5**：自实现 MCP server 时自定义 notification 必须 `extends NotificationParams`（不能 inline object），不然 `_meta` 字段丢了 trace propagation / cache hint / session id 三件套全废。
