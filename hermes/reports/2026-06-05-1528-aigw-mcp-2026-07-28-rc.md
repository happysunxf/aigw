## 1. 头条：MCP 2026-07-28 RC — 去 session、无状态、tasks 转 extension

- 官方 changelog：`https://modelcontextprotocol.io/specification/draft/changelog`，对比基线为 `2025-11-25`。

### 1.2 7 大 Major change

| # | 变更 | SEP | 网关必改 |
|---|------|-----|---------|
| 1 | Streamable HTTP 移除 `Mcp-Session-Id` 头和协议级 session；`tools/list` 不再 per-connection 变化；跨调用状态用 server 签发的 explicit handle 作普通 tool 参数 | 2567 | 移除 `Mcp-Session-Id` 路由/限流/审计分支；LB 退化为普通 HTTP 亲和；"handle"作普通参数记审计 |
| 2 | MCP 无状态化：删除 `initialize` / `notifications/initialized` 握手；每请求 `_meta` 携带 `protocolVersion` / `clientInfo` / `clientCapabilities`；版本不匹配返回 `UnsupportedProtocolVersionError` | 2575 | 按 per-request capability 做授权与配额；多版本同跑按 header 路由到不同 backend pool |
| 3 | 新增 `server/discover` RPC：STDIO 上做版本/能力自描述 | 2575 | discovery 服务把 `server/discover` 列为 first-class 探活；SLO/健康检查更新探针 |
| 4 | `subscriptions/listen` 取代 `resources/subscribe` + 旧 GET endpoint：单一长连接 POST-response 推 4 类 `*ListChanged` / `resourceSubscriptions` | 2575 | "按订阅聚合" → "按 stream 多路复用"；连接复用比上升，断流重试重写 |
| 5 | 删除 `ping` / `logging/setLevel` / `notifications/roots/list_changed`；log level 改 per-request `_meta.io.modelcontextprotocol/logLevel` | 2575 | 探针不能依赖 `ping`；日志级别每请求控制 |
| 6 | **Tasks 从 core 移到官方 extension** (`io.modelcontextprotocol/tasks`)：`tasks/get` 轮询 + `tasks/update` 客户端→服务器输入；删除 `tasks/result` 阻塞 + `tasks/list`；服务器可主动返 task handle 无 opt-in | 2663 | 为长任务建独立 connection pool + 配额；`tasks/result` 阻塞链路留 1 个 deprecation 窗口 |
| 7 | **Multi Round-Trip Requests (MRTR)**：服务器不再发 `roots/list` / `sampling/createMessage` / `elicitation/create`，改返回 `inputRequests`（新 resultType），客户端下一个请求里以 `inputResponses` 回传 | 2322 | **真正的协议级破坏点**：所有"服务器主动拉数据"场景改 pull-based；"callout→callback"假设重写 |

### 1.3 6 条 Minor change（节选）

- `ClientCapabilities` / `ServerCapabilities` 加 `extensions` 字段（与 core 解耦）
- **OpenTelemetry trace context 写入规范**：`_meta` 三个 key `traceparent` / `tracestate` / `baggage`（SEP-414）
- `tools/list` **SHOULD** 确定性顺序返回，提升 LLM prompt cache 命中率（**会改变**依赖 list 顺序做 diff 的缓存策略）
- Streamable HTTP POST 强制两标准头 `Mcp-Method` / `Mcp-Name`；工具参数可通过 `x-mcp-header` 注入自定义 HTTP 头（SEP-2243）
- 新 `CacheableResult` 接口：`tools/list` / `prompts/list` / `resources/list` / `resources/read` / `resources/templates/list` 必须返回 `ttlMs`（毫秒新鲜度）+ `cacheScope`（`"public"`/`"private"`）— 直接利好中间代理缓存
- 资源 not found 错误码从 `-32002` 改 `-32602`（JSON-RPC 标准 Invalid Params）

### 1.4 Deprecated / 治理

- `Roots` / `Sampling` / `Logging` 正式 deprecate（SEP-2577）。替代：Roots → tool 参数 / resource URI；Sampling → 直调 LLM provider；Logging → `stderr` (stdio) 或 OTel
- HTTP+SSE 传输（2025-03-26 起软 deprecate）按 feature lifecycle policy 重新归类 Deprecated
- `includeContext` 的 `"thisServer"` / `"allServers"` 升级 Deprecated
- 政策：进入 Deprecated 后**最少 12 个月**才进 Removed
- 新增 **Feature Lifecycle & Deprecation Policy**（SEP-2596）；SEP 改 **PR-based**（SEP-1850）

## 2. 官方 SDK 同步

### 2.1 Python SDK v1.27.2（2026-05-29，**最关键**）

四个 backport 全部围绕 **per-session security binding**：

- **PR 2690**：AccessToken 补 OIDC 风格 `subject` / `claims`
- **PR 2719** *Bind transport sessions to the authenticated principal*：Streamable HTTP / SSE 传输的每个 session 记录"创建它的 principal"（OAuth client + issuer + subject），后续请求 principal 不一致 → **404**（与 unknown session 同响应，避免枚举）。SSE 断开立刻清 session 条目，**不再**保留到 transport 生命周期结束
- **PR 2720** *Scope experimental tasks to the session that created them*：`run_task()` 生成的 task ID 嵌入 per-session marker（长度 36→69 字符）。默认 handler 的 `tasks/get` / `tasks/result` / `tasks/cancel` 跨 session 返 "task not found"；`tasks/list` 只返本 session 的 task。**直接落实** spec 2025-11-25 的"authorization context"要求
- PR 2635：文档站切到 GitHub Pages artifact 部署

> 生产用 FastMCP 的应**升级**。注意：手写 SSE 用 `BearerAuthBackend` 只挂 POST 不挂 GET 的部署会"全 404" — SDK 现在按 principal 校验后续 stream 上的消息。

### 2.2 Go SDK v1.6.1（2026-05-22）

- 引入 `MCPGODEBUG=disablecontenttypecheck=1`，可关掉 Streamable HTTP / SSE 的 `Content-Type: application/json` POST 校验（PR #972 / Issue #957）
- 上下文：v1.6.0 把跨域保护从"默认开"改"opt-in `enableoriginverification`"，但 Content-Type 校验没留 escape hatch → 1.6.1 补回
- **对网关**：跨域宽松的代理在 Go SDK 升 1.6.x 时要确认仍能正常转发非 `application/json` 的回调（SSE 客户端可能用 `text/event-stream` 触发 POST）

### 2.3 TS SDK 2.0.0-alpha.2（2026-04-01） + Inspector 0.22.0（2026-06-04，**最新**）

- `server@2.0.0-alpha.2` + `node@2.0.0-alpha.2` 同时发布；TS 在追 RC 的无状态化 / capability-per-request 改造，**不要在生产用 alpha**

## 5. AI Gateway 团队的"实操清单"（基于 RC）

> 自建/运维一个**对外暴露 MCP server 的 AI Gateway** 必做：

1. **移除 `Mcp-Session-Id` 路径**：路由/限流/审计改"per-request principal + handle"
2. **实现 per-request capability**：每请求读 `_meta` 的三个 `io.modelcontextprotocol/*` 字段，授权与配额按 capability 重新映射
3. **探针更新**：禁用 `ping`；改用 `server/discover` 或裸 HTTP 200
4. **长任务分流**：标 `tasks/result` 阻塞 deprecated；为 `tasks/get` 轮询 + `tasks/update` 建独立连接池
5. **MRTR 重写**：所有"服务器回拉数据"从 push（`sampling/createMessage` / `elicitation/create` / `roots/list`）切到 `inputRequests` / `inputResponses` 双向 pull
6. **缓存层升级**：在 5 个 list endpoint 上读新 `CacheableResult.ttlMs` + `cacheScope`，建 per-(tool, scope, ttl) 共享缓存（list 顺序非确定是 LLM cache miss 常见来源之一）
7. **OTel 头透传**：把 `_meta.traceparent` / `tracestate` / `baggage` 与现有 W3C Trace Context 关联，**不要再丢弃** `traceparent`
8. **HTTP 头白名单**：`Mcp-Method` / `Mcp-Name` 必传（审计字段），自定义头走 `x-mcp-header`（**避免任意 header 透传绕过 WAF**）
